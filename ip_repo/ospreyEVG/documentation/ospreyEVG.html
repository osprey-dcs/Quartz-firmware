Software

Initialization

An application must initialize the the hardware interface before calling any of the other routines.  Initialization is performed by invoking

int ospreyEVGInit(uint32_t baseAddress);

The return value is 0 if registration succeeded and -1 otherwise.  If the block design component name is ospreyEVG the memory-mapped I/O base address to pass as the argument will be defined in the board support xparameters.h file as XPAR_OSPREYEVG_S_AXI_BASEADDR.

Status

The status of the event generator is returned by

int ospreyEVGStatus(void);

Returns the event generator status word:

Time of Day

The time of day sent by the event generator is initialized by invoking
int ospreyEVGSetSeconds(uint32_t posixSeconds);
Once set the seconds value is incremented by each rising edge of the PPS marker.

Heartbeat Events

The rate at which heartbeat events are generated is the evgClk divided by the divisor set by invoking
int ospreyEVGSetHeartbeatDivisor(uint32_t divisor);

Timer-requested Events

The event and rate at which timer-requested events are generated  are set by invoking
int ospreyEVGSetTimerEvent(int index, int evCode);
int ospreyEVGSetTimerDivisor(int index, uint32_t divisor);
The rate is the evgClk divided by by the specified divisor.  An index value of 0 corresponds to the first timer.  An event code of 0 disables the associated timer.  A divisor less than or equal to 1 sets the divisor to its maximum value (2^32-1).

Hardware-Triggered Events

The event and rate at which timer-requested events are generated  are set by invoking
int ospreyEVGSetHwTriggerEvent(int index, int evCode);
An index value of 0 sets the event code to be triggered by a rising edge on the first hardware trigger input. 
An index value of 1 sets the event code to be triggered by a falling edge on the first hardware trigger input.
 An index value of 2 sets the event code to be triggered by a rising edge on the second hardware trigger input, and so on.
An event code of 0 results in no event being triggered by the associated edge and input.

Software-Triggered Events

An arbitrary event code is transmitted by invoking
int ospreyEVGSendSoftwareEvent(int index, int evCode);

Event Sequencer

Event patterns are written to the sequencer RAM by first calling
int ospreyEVGSequencerLatchDelay(int delay);
where the delay is a 28 bit value.  If the most significant bit of this value is clear, the remainder of the bits specify the delay before the next event is emitted in units of event generator clock ticks.  Full scale value with a typical event clock period of 8 ns is a little more than one second.  If the most significant bit of this value is set, the remainder of the bits specify the delay before the next event is emitted in units of 64 event generator clock ticks.  The full scale value in this case is a little more than one minute.  Delays longer than this can be obtained by chaining together multiple delays with an event code of zero.
Note that calling this routine does not write anything to the sequencer RAM – rather it simply latches the value internally for a subsequent call to
int ospreyEVGSequencerWrite(int value);
where the least significant eight bits of value are the event code to emit after the delay currently in the latch mentioned above and the next most significant twelve bits are the sequencer RAM location into which the value will be written.  A sequence is terminated by an event code of all ones (255).

Once an event sequence has been loaded it is emitted by first calling
int ospreyEVGSequencerArm(void);
followed by a hardware trigger or a call to
int ospreyEVGSequencerTrigger(void);

An armed sequencer or active sequence can be terminated by calling
int ospreyEVGSequencerCancel(void);

Event Source Priorities

If multiple event sources make simultaneous requests the event from the lower priority source will be delayed and emitted at the next free slot, in most cases.  The event source priorities are:

  • Sequencer events.
  • Timer-driven events.  The first timer (index 0) has the highest priority.
  • Hardware-trigger-driven events.  The first hardware input (index 0 or 1) has the highest priority.
  • Software-requested events.
  • Heartbeat events.  If preempted the event is omitted rather than being shifted to the next free slot.
  • Pulse-per-second events.
  • Time-of-day updates.  There is no problem with these events (112 and 113) being delayed as long as all 32 have been sent before the next pulse-per-second event.


EPICS

Example EPICS database entries to control the event generator are included in the distribution.  The entries use the LEEP protocol to communicate with the FPGA.  All record names in the example database begin with the $(P) macro.  This prefix is not included in the record names below.

To include the EPICS database in an EPICS application:
  • Add an OSPREY_EVG entry in the application configure/RELEASE or configure/RELEASE.local.
    The entry should refer to the EPICS directory in the ospreyEVG support module.
  • Add two lines to the application Db/Makefile:
    USR_VPATH += $(OSPREY_EVG)/db
    DB += ospreyEVG.db

Status

The longin record status holds the status register contents described above.

Heartbeat Events

The rate at which heartbeat events are generated is the evgClk divided by by the divisor set by the hbDivisor longout record.

Timer-requested Events

The rate at which timer-requested events are generated is the evgClk divided by by the TMR:n:divisor longout records, where n is 1 or 2.   The event code emitted is set by the TMR:n:event longout records.  An event code of 0 disables the associated timer.  A divisor less than or equal to 1 sets the divisor to its maximum value (2^32-1).

Hardware-Triggered Events

The event code emitted on the edge of the signal at each hardware trigger input is set by the TRIG:n:rise or TRIG:n:fall longout records where n ranges from 1 through 4.  An event code of 0 disables the associated trigger.

Software-Triggered Events

An arbitrary event code is transmitted by writing the code to the swEvent longout record.

Event Sequencer

Event sequences are a described by a table of delay:event pairs, where the delay is the number of evgClk ticks to wait before emitting the specified event.  Thus a delay value of 0 means that the event is emitted in the next event code slot following the previous event.  The table is written the to sequencer memory by first writing the desired delay value to the SEQ:latchDelay longout record and then the sequencer memory address and event to the SEQ:write longout record.  The least significant eight bits of the value specify the event code nad the next most significant twelve bit specify the memory address to which the latched delay value and event will be written.  The end of the table is indicated by an event code of 255.  Delays are specified as 28 bit values.  If the most significant bit of this value is clear, the remainder of the bits specify the delay before the next event is emitted in units of event generator clock ticks.  Full scale value with a typical event clock period of 8 ns is a little more than one second.  If the most significant bit of the delay value is set, the remainder of the bits specify the delay before the next event is emitted in units of 64 event generator clock ticks.  The full scale value in this case is a little more than one minute.  Delays longer than this can be obtained by chaining together multiple delays with an event code of zero.

Once an event sequence has been loaded it is emitted by first processing the SEQ:arm binary-out record and then processing the SEQ:swTrig binary-out record (the value written to the records is unimportant).  An armed sequencer or active sequence can be terminated by processing the SEQ:cancel binary-out record.

If no table entry holds an event value of 255 the 4096-entry sequence will be emitted continuously until the SEQ:cancel binary-out record is processed.
